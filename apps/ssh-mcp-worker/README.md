# ssh-mcp-worker

Independent MCP app for sanitized discovery and bounded one-shot SSH execution against saved EdgeSSH hosts. It uses the existing `@mcp-workers/portal-auth` package and reads the existing EdgeSSH host catalog through fixed, parameterized D1 `SELECT` statements. The D1 binding is write-capable at the platform level; SELECT-only is enforced by this application's code and review.

The app exposes `list_hosts`, `get_host`, `ssh_exec`, `sftp_list`, `sftp_read_text`, `get_operation_status`, `ssh_session_start`, `ssh_session_input`, `ssh_session_stop`, `ssh_session_output`, and `ssh_session_status`. The SQLite-backed `SshOperationsDO` owns receipt admission, live managed PTY shells, and shared four-total/two-per-host SSH connection leases. `sftp_list` and `sftp_read_text` reserve that same lease, open one short SSH connection, and close it after success, failure, or the deadline. They do not create a managed session or a mutation receipt. A directory reply returns at most 100 entries and marks truncation. A text read returns at most 64 KiB of valid UTF-8; a larger file or non-UTF-8 bytes is refused with `output_truncated` and no file body. The SFTP deadline defaults to 30 seconds and cannot exceed 60 seconds, including connection setup. Paths over 4 KiB UTF-8 are rejected before a lease or connection. Establishing a shell counts against that same lease, including while the start is still in flight; there is no extra long-session pool. Output polling does not extend a shell. Idle closure is 10 minutes from the last authorized activity and the absolute cap is 60 minutes, enforced by a Durable Object alarm and by the next DO request. Either deadline, a remote disconnect, or a DO restart drops the TCP connection. Restart or disconnect is reported as `lost` and is not reconnected, replayed, or treated as ownership of a remote process. The live output ring keeps 256 KiB and each read returns at most 64 KiB, with truncation when older bytes were evicted or the read is shorter than the retained tail. It records an operation ID and canonical intent digest before target resolution or SSH dispatch; same-ID retries return stored metadata and cannot redispatch. The digest input is the JSON tuple `[tool, lower-case host_id, lower-case session_id or null, normalized_args]`; `ssh_exec` uses `[command, timeout_ms]`, `ssh_session_start` uses `[term_type]` with the default `xterm-256color`, `ssh_session_input` uses `[input]`, and `ssh_session_stop` uses `[]`. Argument arrays are restricted to ordered JSON scalar values. Interactive input is serialized per live shell, re-reads the saved host, and closes that owned channel when the record is gone or its target, pin, username, auth method, or credential changes; `updated_at` is not the change signal. The same input operation id never resends bytes. A normal stop closes the owned channel and TCP socket and reports `remote_descendants: not_observed`. When a receipt cannot be written, new input and commands are rejected, but one stop of a channel that is still live in this Durable Object is attempted and labeled `unknown` / `unverified`. Status and output reads do not write to the shell or open a connection. Every `/mcp` call, including input and stop, checks the Portal bearer again. Receipts written by the initial `ssh_exec` implementation remain recognizable using its legacy `[tool, host_id, command, timeout_ms]` digest tuple; no receipt rows or DO identity are reset during this compatibility check. The e2e fixture pins current vectors for exec, session input and SFTP write plus the legacy exec digest. Results are bounded and command input is limited to 16 KiB UTF-8. Known terminal receipts are opportunistically deleted during effectful requests once their admission time is at least 30 days old, at most 50 rows per request using the `(status, created_at)` index. Further requests continue pruning eligible rows. After cleanup, the service cannot recognize that old ID; clients must use a fresh UUID for each intention and must not retry an expired ID. Unknown or ambiguous receipts are retained as minimal no-replay tombstones without age expiry.

SSH execution and short SFTP calls re-read the current saved record in the DO, reject an absent or malformed pin before authentication, resolve DNS once through DNS-over-HTTPS, reject any private/reserved answer, and inject a socket that connects only to the selected validated numeric IP. SSH host signature verification and SHA256 pin comparison use the G0-selected `@meitaim/ssh` runtime before credentials are sent. Port 25 and non-public numeric targets are rejected. Remote stdout, stderr, and SFTP file text are untrusted host output and may themselves contain secrets; stored connection credentials and the encryption root are never included in receipts, tool results, or errors.

Each tool result is bounded to 64 KiB including its MCP content representation and a reserved transport envelope. `list_hosts` applies both the requested row limit (at most 200) and a UTF-8 byte budget; when a page fills by bytes, `nextCursor` points to its last returned host so the next request resumes without skipping the first host that did not fit.

## Local checks

Requirements: Node `>=24 <25`, pnpm `10.17.1`, and `ssh-keygen` for the retained G0 runtime probe.

```sh
pnpm install --frozen-lockfile
pnpm --filter ssh-mcp-worker typecheck
pnpm --filter ssh-mcp-worker test
pnpm --filter ssh-mcp-worker test:g0
pnpm --filter ssh-mcp-worker test:exec
```

`typecheck` checks the Worker and Node test types. `test` exercises the real `/mcp` handler with synthetic D1 fixtures and proves oversized commands are rejected before any catalog lookup or DO call. `test:g0` runs the selected SSH implementation in local workerd against disposable SSH fixtures. `test:exec` starts the actual MCP handler with a local SQLite-backed DO, synthetic encrypted D1 row, and disposable SSH peer. Its test-only Worker entrypoint maps the synthetic fixture hostname to loopback; that routing override is not included in the deployable Worker entrypoint. The end-to-end check covers atomic concurrent same-ID admission, fail-closed storage failures, a real Wrangler restart preserving the local DO database, interruption during an active SSH command, pre-dispatch and post-effect uncertainty recovery, legacy receipt replay after restart, changed-intent conflicts, fixed current/legacy digest vectors, query-plan use of the cleanup index, the 50-row cleanup bound and eventual cleanup, unknown tombstone retention, output bounds and secret-free receipts. It also covers managed-shell start, cross-request output and status, shared connection leases, the 256 KiB ring and 64 KiB reads, remote disconnect, idle or absolute closure through a simulated clock, an explicit alarm, and the next DO request, idempotent PTY input, controlled stop, host-record drift, and emergency stop when receipt admission fails. These checks do not cover public DNS/network success, a deployed DO, production Portal/D1/Secrets, cloud eviction, or a wall-clock 60-minute TCP session.

## Recreate the upstream compatibility fixture

The checked-in fixture was generated by the exact pinned EdgeSSH `encryptHost` implementation. To reproduce it, fetch the source revision into a temporary directory and run:

```sh
git clone --filter=blob:none --no-checkout https://github.com/lirtual/EdgeSSH.git /tmp/edgessh-7a051e4
git -C /tmp/edgessh-7a051e4 checkout --detach 7a051e412d2cfa4ee52edec30e6ccefedb4e1c99
node --experimental-strip-types apps/ssh-mcp-worker/scripts/generate-host-fixture.mjs /tmp/edgessh-7a051e4/src/accounts/crypto.ts > /tmp/edge-ssh-host-v1.json
diff -u apps/ssh-mcp-worker/tests/fixtures/edge-ssh-host-v1.json /tmp/edge-ssh-host-v1.json
node --experimental-strip-types apps/ssh-mcp-worker/scripts/generate-host-fixture.mjs /tmp/edgessh-7a051e4/src/accounts/crypto.ts --long-catalog > /tmp/long-catalog-v1.json
diff -u apps/ssh-mcp-worker/tests/fixtures/long-catalog-v1.json /tmp/long-catalog-v1.json
```

The generator fixes synthetic AES-GCM IVs so the source output is reproducible. The included key, account/host IDs and payload are artificial. The payload intentionally contains canary credential and `initialCommand` strings; tests verify they never leave the sanitized view.

## CI selection

The existing application selector includes `ssh-mcp-worker`. Changes under `apps/ssh-mcp-worker/**` select its check. Shared package, workspace, root package and lockfile changes select every app, including this one; the existing affected-application step invokes `pnpm --filter ssh-mcp-worker check`. CI runs `node --test scripts/select-affected-apps.test.mjs` to cover app-only and shared package/lockfile selection. The Worker is not added to the workflow's production release choices.

No deployed D1 ID or secret is committed here. A binding to the existing EdgeSSH database and MCP secrets require later operator-controlled configuration.

# Weixin MCP Worker — bounded context (Spec #346)

Owns the **single-owner** Weixin ClawBot binding, bounded authenticated iLink monitoring, and explicit outbound text. Excludes arbitrary friends/groups, inbound chat mirroring, background notifications, and a full OpenClaw Gateway.

**Status: PR #348 merged and Worker deployed; ChatGPT status and one handset-confirmed send passed on 2026-10-27.** The first production send had an ambiguous `unknown` API receipt despite observed handset delivery. `ready` indicates bound identity, not guaranteed live context or handset delivery. This follow-up change adds on-demand owner-context refresh before new sends. Long-idle recovery remains unverified pending authorized production testing.\n\nThe implementation serializes send, cursor sync and local unbind with a 120-second D1 lease; request IDs remain unique across generations. An already dispatched upstream write cannot be cancelled, and expiry is a bounded recovery mechanism, not exactly-once delivery. **QR issuance, polling and activation acquire the same lease.** Rebind and QR verification passed the local workerd/D1 and signed Access-mock checks; live owner Access, Cloudflare D1 concurrency, and Tencent protocol acceptance remain necessary before public exposure. No Cron, durable object, queue or retry scheduler without measured necessity.

Follow [Issue #346](https://github.com/lirtual/mcp-workers/issues/346). Production deployment and Portal registration of these follow-up changes require normal release authorization; no automatic resend of unknown receipts.\n

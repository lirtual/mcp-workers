# RCA Rust Native Agent — Gate 0 verified / Gate 1 candidate

This crate is an unshipped migration candidate for [Spec #914](https://github.com/lirtual/mcp-workers/issues/914). Gate 0 passed and merged in PR #915; Gate 1 signed WSS transport was merged in [PR #916](https://github.com/lirtual/mcp-workers/pull/916). The native read_file plus file-browsing executors are Gate 1 candidate slices, not overall Gate 1 completion. The TypeScript/Node Agent remains authoritative. No supported Agent CLI, installer, Worker or Release workflow executes Rust.

Verified seams:

- Node 24's `operationDigest` custom JSON ordering, floating-point formatting and SHA-256, using fixed independent golden cases.
- Node 24's Ed25519 PKCS#8/SPKI session and Owner-intent signing transcripts; disposable public test seed generated in memory.
- Isolated loopback signed WebSocket challenge, explicit denial/invalid subprotocol rejection, bounded TCP connect and per-I/O TLS/WebSocket handshake waits, ping-frame handling, and one test-only read/write roundtrip through the guarded Rust `Gate0Probe` with persistent receipt and no-blind-replay on reconnect.
- Negative Gate 0 tests reject public/symlinked/wrong-name roots, out-of-scope paths, append-mode writes and malformed/oversized frames before mutation.
- Actual Worker source (`src/worker.ts`) with SQLite Durable Object and throwaway temporary Owner Grant: signed Rust WebSocket, fresh file write, process restart, persisted same-ID status, idempotent same-ID replay, different-intent conflict and successful file read. Verified over local Wrangler, a short-lived HTTPS/WSS Cloudflare Quick Tunnel, and a disposable **Cloudflare-hosted** Worker account.
- Durable SQLite `user_version=1` receipts, legacy JSON import, exclusive ownership, interrupted-operation Unknown and no-blind-replay, with a Node → Rust → Node interoperability test.
- Gate 1 **nonproduction Rust native `read_file`, `read_multiple_files`, `list_directory`, `get_file_info`**: strict authenticated `read` envelope and UUID validation before queueing, Node-compatible local path/offset/length validation, ordinary/tail line reads with a 1 MiB scan cap, nonblocking regular-file check, lossy UTF-8 handling, 200K UTF-16-char and 65,536-byte encoded WSS reply caps without truncated secrets, and failed `read_result` on invalid path/arguments. The separate reader thread keeps signed WSS heartbeat and Grant probes alive. The three browse tools use the existing authenticated read transport and match Node's batch file blocks/failed-file isolation, depth-1–3 directory pre-order traversal (100-entry cap, no symlink following), and lstat file details. Unmigrated search/process tools, writes and Shell are not admitted by this limited native read transport (policy 1008); no device capability is advertised. Signed loopback WSS tests verify a real file read and denied mutation. A disposable **real Worker + SQLite DO + temporary Owner Grant** has now independently delivered an MCP `read_file` call to Rust and received exact file contents; unauthorized Owner 401 and revoked identity fresh-challenge denial were also observed. The opt-in `wrangler_native_read.rs` test records this flow without touching production.
- Gate 1 signed WSS `rc-v2:ping/pong`, per-nonce periodic Grant validation, bounded transport queue, connection-specific revocable execution leases and response incarnation isolation. Bounded 1/2/4/8/16/30s reconnect reclaims a fresh signed challenge on transient faults (including 408/425/429/5xx); HTTP 401/403/404, 1008 and incompatible protocol stop permanently, `superseded` ends cleanly. A shared Stop signal fences already queued requests immediately and prevents new post-Stop admissions. A real local Wrangler + SQLite DO temporary Grant passed the 30-second rate gate, valid auth ACK, Owner `revoke_cleanup`, 1008 closure and fresh challenge denial. No real process execution or cleanup is provided by this transport crate.

- Gate 1 **disposable combined file-session proof**: `run_disposable_file_session` connects the existing signed WSS heartbeat/Grant/Stop transport to the previously verified SQLite-backed Gate 0 `Gate0Probe`. The only permitted mutation remains a fresh `probe.txt` in an owner-private `rca-rust-probe-*` test directory (mode 0600); matching operation IDs return the existing persisted result, changed arguments conflict, and a new executor can read the completed receipt after restart. Both root validation and SQLite ownership occur before WSS admission; Stop/revocation fences queued operations and stale replies. This is intentionally **not** a general Agent write path: it does not implement Node's existing-file rewrite/append semantics, advertise device capabilities, or issue the full native read protocol; malformed test-only operation frames stop this candidate session without guaranteeing a 1008 close frame. It is never packaged or deployed.

- Gate 1 **native `write_file` core**: strict Node-compatible local argument bounds (49,152 UTF-8 bytes), path validation and lexical normalization before canonical SHA-256 receipt admission, mandatory live lease checks both before admission and after SQLite state persistence (pre-effect), `rewrite` and `append` behavior, in-place rewrite preserving symlink/hardlink/open-handle inode semantics, and no-blind-replay after restart. Linux new-file staging is limited to verified private ext-filesystem parents; a private 0600 temp is hard-linked without overwrite, with Node's effective umask applied to the final file. Other filesystems retain the legacy create/truncate behavior and classify any post-open failure as Unknown. Tests cover existing files, symlink/hardlink, UTF-8 cap, mode, no-effect failure, duplicate/conflict, interrupted receipt, and secret-free persisted receipts. This core is also wired into a separate **non-installable native file session** (`run_native_file_session`): the signed WSS+Grant/Stop transport strictly admits authenticated native read/file-browse, `write_file`, `create_directory`, `delete_file` and `get_operation_status` frames; malformed or other tool frames close with policy 1008 before execution. The shared bounded request queue uses connection-scoped revocable leases, and persisted receipts are opened exclusively before WSS admission. Seven signed loopback tests cover read/write, same-ID idempotence and changed-intent conflict, receipt recovery after restart, invalid arguments, denied Shell/process execution, and revoked leases. An opt-in **real local Wrangler + SQLite Durable Object + temporary Owner Grant** test (`wrangler_native_file.rs`) passed Owner MCP write/read/idempotence/conflict/status plus revocation challenge denial using a disposable device and private `/tmp` fixture. The older `run_disposable_file_session` continues to use the narrower Gate 0 probe. Windows ACL equivalence, interrupted staging/races on real ext mounts, real device lifecycle/CLI, additional tools and release integration remain unverified. No supported Agent capability is advertised, and no production device or Worker was changed.

- Gate 1 **native directory creation and regular-file deletion candidate**: `create_directory` is single-level (no recursive parents); `delete_file` uses lstat and refuses directories, symlinks and nonregular targets before unlink. Both reuse Node-compatible normalized path-only SHA-256 admission, `operation_id` conflict/no-blind-replay semantics, SQLite receipts and per-connection live lease checks before admission and immediately before effects. `native_dir_delete.rs` covers successful effects, idempotence, changed-intent conflicts, restart, invalid input, revoked lease, failed parents and symlink refusal. Signed WSS now permits both tools and rejects malformed frames with 1008. The isolated opt-in `wrangler_native_file.rs` additionally passed actual Owner MCP directory creation, ordinary-file deletion, repeated-ID no-replay, refusal to delete a directory, and revoked identity denial. The real Windows/macOS filesystem, installer and release chain remain unverified.

- Gate 1 **native `edit_block` candidate**: strict Node-compatible UTF-8 argument limits (49,152 bytes for old/new strings), optional expected replacement count defaults to 1 (1–1000), and lexical path normalization before SQLite receipt admission. The executor checks stable original file identity/content, validates UTF-8, counts non-overlapping exact matches, then reopens and rechecks identity/content immediately before an in-place rewrite. A mismatch or invalid text fails without changing the target; errors after truncate are guarded Unknown and never blindly replayed. Shared WSS/receipt/Grant/Stop state and default-vs-explicit count hashing are reused, with signed 1008 policy failures for malformed frames. `native_edit.rs` verifies count mismatch, Unicode, symlink/hardlink/open-handle inode preservation, cross-tool conflict, revocation and restart idempotence. Isolated real local Wrangler + SQLite DO + temporary Owner Grant passed actual MCP replace_text, duplicate-ID no-effect, changed-intent conflict, count-mismatch no-effect and revocation denial. Like Node, compare-before-write is best effort against external concurrent writers, not an OS-atomic CAS; real Windows/macOS behavior and shipping lifecycle remain unverified.

- Gate 1 **native `move_file` candidate**: strict source/destination path validation and Node-compatible lexical normalization; source must lstat as a regular file, source and destination must differ, and only a same-filesystem hardlink-then-unlink move is attempted (no overwrite or implicit copy). If source unlink fails, the new destination hardlink is removed; failed rollback becomes a guarded Unknown receipt. The existing shared SQLite/lease state machine preserves same-ID no-replay and cross-tool conflict after restart. `native_move.rs` tests inode preservation, target collision, invalid/symlink/directory sources, same-resolved-path refusal, revoked leases and a real permission-induced unlink rollback on ordinary Linux users. Signed WSS also rejects invalid move frames with policy 1008. A disposable local Wrangler Worker + SQLite DO + temporary Owner Grant returned completed for Owner MCP move, same-ID safe replay, changed-intent conflict and revoked-grant challenge refusal. Physical Windows/macOS hardlink/ACL behavior remains unverified; no shipping Agent has been changed.

### Linux managed-session Supervisor control (nonproduction only)

The Linux-only `linux_supervisor` Rust module reuses the **existing** `agent/scripts/session-supervisor.c` binary and its native fd 3/4 single-byte protocol; it does not create another supervisor, service, dependency or release asset. Rust creates a private process group, passes private control pipes, accepts the ready handshake, and can request TERM, escalate to KILL and close the owning channel. The C helper retains the `pidfd_send_signal(..., PIDFD_SIGNAL_PROCESS_GROUP)` preflight, subreaper and fail-closed process-group cleanup. Rust reports `CleanupState::Confirmed` only when the C subreaper returned normally (excluding ambiguous exit 125); any signal-killed supervisor, including KILL escalation and channel loss, is `Unknown`, even when a particular child is observed dead. No caller-supplied PID is signalled.

Three opt-in Linux tests with the existing C helper passed: owned shell/group TERM, control-pipe EOF, and a TERM-ignoring command requiring KILL. They independently check whether the started child is still executing (a reparented zombie is not a live process). The separate unshipped `linux_output` module now continuously drains both stdout/stderr pipes with a shared **256 KiB** capture cap (it keeps discarding further bytes to avoid child backpressure), paginates by byte offset with Node-compatible UTF-8 boundaries (up to 64 KiB requested), and stops its readers within bounded poll intervals even when a pipe remains open. Four opt-in real Linux tests cover large dual-stream output, early reader stop, multi-byte pagination and the incomplete UTF-8 cap boundary. The output-only `eof` means both pipes closed; any future WSS session response must additionally check process state before promising process completion.

The unshipped `linux_command` module now composes the C Supervisor and bounded output into a **single blocking Linux command** for disposable hosts. It preserves Node's 8192-UTF-16-unit/NUL input check and 60-minute maximum, polls a shared cancellation flag, stops owned descendants on expiry/cancellation, returns the independently observed exit and cleanup status, and waits a bounded time for pipe closure. Output EOF alone never establishes process completion; SIGKILL or uncertain cleanup is explicitly Unknown, even if a particular child appears dead. Seven opt-in real-process checks exercise success, nonzero exit after early pipe EOF, deadline and cancellation with descendant verification, KILL uncertainty, pre-cancel and invalid input.

The blocking proof is deliberately not routed through the Worker (whose response budget is much shorter). The separate, Linux-only **`linux_managed`** candidate adds a background session registry over that same C helper and bounded output capture: startup returns after the native ready handshake, output remains page-readable while the process runs, 10 active/uncertain sessions are admitted, completed history is bounded to 10 and 30 minutes, and a spawn-relative absolute lifetime is capped at 60 minutes. Owner-style bulk stop closes new admissions first and only reports confirmed cleanup after each owned C supervisor was reaped; KILL escalation and any unconfirmed cleanup remain Unknown and conservatively consume capacity. Eleven opt-in physical-process tests now additionally cover UTF-8 stdin roundtrip, invalid input and revoked-session rejection, plus unread-pipe backpressure returning Unknown within a one-second write budget. Stdin writes are nonblocking and bounded to 8192 UTF-8 bytes (Node-compatible); a failed/partial write must never be blindly replayed. A pending owned entry is reserved before native startup, so concurrent revocation never waits on the handshake lock; unproven startup/cleanup retains Unknown rather than being omitted from the registry.\n\nThis candidate is **not yet an authorized WSS executor**: no durable process receipt admission, session-to-receipt reconciliation, authenticated WSS stdin/stop dispatch, Windows/macOS process control, installer or installed Agent CLI exists. The caller must run process work off the WSS heartbeat loop and must not infer success from the output EOF flag. No Rust command capability is advertised, packaged or deployed.

For the opt-in tests, build the repository's existing C helper in the disposable checkout with `node agent/scripts/build-session-supervisor.mjs`, then set `RCA_NATIVE_SUPERVISOR_BIN` to its absolute `agent/.build/session-supervisor` path when invoking `cargo test --locked --test linux_supervisor --test linux_output --test linux_command --test linux_managed -- --ignored`. Do not use a real device or production identity.

### Linux process-boundary tracer (nonproduction only)

`cargo run --locked --bin rca-native-nonprod -- --local DEVICE_UUID /tmp/rca-rust-probe-UNIQUE` launches the existing signed native file session as a standalone Linux process. It only connects to the **exact** local Wrangler address `http://127.0.0.1:8777/` and requires a separately approved disposable identity at `gate0-test-key.pem` directly under `/tmp` in an owner-owned, non-symlinked `rca-rust-probe-*` directory (0700; identity 0600, single link). A validated `gate0-test-key.pem.owner-stopped` marker blocks connection; invalid markers fail closed. SIGINT/SIGTERM stop the bounded reconnect loop. Existing Node Agent state paths, root execution and production endpoints are rejected.

This is **not** an installed CLI, filesystem sandbox, pairing client, supervisor or released Agent. A disposable local Worker can still authorize file operations with the current OS user's permissions; execute it only in an isolated, throwaway test host with known temporary file targets. The CLI process rejection/Stop tests are in `tests/nonprod_cli.rs`; the real-Owner WSS/file library contract remains in the opt-in `wrangler_native_file.rs`. The opt-in `wrangler_cli_process.rs` now verifies a **real Owner MCP → local Wrangler/SQLite DO → separate CLI subprocess** with a fresh temporary Grant: write/read, durable status, same-ID no-replay, changed-intent conflict and clean SIGTERM (Pass on an isolated Linux runner). The same test now restarts the process against its preserved private SQLite state, proves a new Owner write succeeds, then revokes the temporary Grant while its WSS is active: the process exits within 10 seconds and a subsequent Owner mutation produces no file effect. Its identity and Owner token come only from a separately approved private `/tmp/rca-gate1-file-*` fixture, never from an installed Agent; the fixture Grant and test files are removed after verification. In-flight long-running process cleanup, installation and upgrades remain unverified.

Test in a **disposable** checkout:

```sh
cargo fmt --all -- --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked --all-targets

# Opt-in only: local Wrangler on 127.0.0.1:8777 and a fresh, privately
# approved temporary fixture (native-test-key.pem, device-id, owner-token).
RCA_LOCAL_NATIVE_FILE_ROOT=/tmp/rca-gate1-file-TEST cargo test --locked \
  --test wrangler_cli_process owner_file_receipt_and_sigterm_reach_real_cli_process \
  -- --ignored --exact --nocapture
```

Node 24 is required only for the interop test. The Rust library does not require Node at runtime.

### Disposable real-Worker verification adapter (unshipped)

The `gate0_nonprod` Cargo **example** is a bounded, Unix-only test client, not a supported Agent executable. It refuses the production hostname and accepts only an explicitly named `rca-rust-gate0-*.workers.dev` preview, the exact `http://127.0.0.1:8777/` with `--local`, or a one-label `*.trycloudflare.com` URL with `--quick-tunnel`. It reads only `gate0-test-key.pem` inside an owner-private absolute `rca-rust-probe-*` directory; this must be a separately created, **throwaway** PKCS#8 identity (0600), approved only in a disposable nonproduction Owner Grant. Never copy an existing paired Agent key or receipt folder. It handles 1–8 prearranged frames and exits; reconnect/status verification requires a fresh process and challenge while preserving only that same disposable SQLite directory.

```sh
# Dedicated disposable preview Worker, when independently provisioned:
cargo run --locked --example gate0_nonprod -- \
  https://rca-rust-gate0-TEST.account.workers.dev/ DEVICE_UUID \
  /tmp/rca-rust-probe-TEST 1

# Isolated local Wrangler on 127.0.0.1:8777, with a private test-only Owner Grant:
cargo run --locked --example gate0_nonprod -- \
  http://127.0.0.1:8777/ DEVICE_UUID /tmp/rca-rust-probe-TEST 1 --local

# Temporary TLS/WSS tunnel to that same isolated local Worker:
cargo run --locked --example gate0_nonprod -- \
  https://ONE-OFF.trycloudflare.com/ DEVICE_UUID \
  /tmp/rca-rust-probe-TEST 1 --quick-tunnel
```

2026-11-20 evidence: isolated Wrangler, HTTPS/WSS Quick Tunnel, and disposable Cloudflare-hosted Worker tests passed with temporary grants. No production Worker, existing paired device, account secret or release was changed. All disposable local/tunnel/hosted test credentials and Worker resources are removed or allowed to expire after verification.

**Gate 1 remains Partial:** the native file-read and browse libraries are wired into a non-installable WSS runner, but device-info/capability announcement, search tools, Shell and managed process execution, full Windows filesystem metadata/ACL equivalence, five-platform CLI/install/lifecycle, GitHub-hosted Sessions, release/rollback remain unverified or unimplemented; #912 root and #911 Legacy remain independently gated. The cleanup callback may return `confirmed` only after the future real executor verifies all owned processes stopped; otherwise the current transport reports `uncertain`. Worker rate-limits Grant probes for the first 30 seconds and again within 30 seconds after a prior probe; the default Rust cadence is 15 minutes. The local test-only effect is not a production executor. The current candidate refuses unchecked non-Unix private state. Never point it at a real paired device, current identity, or live receipt directory while another Agent can run.

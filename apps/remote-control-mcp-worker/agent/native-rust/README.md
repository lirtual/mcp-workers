# RCA Rust Native Agent — Gate 0 verified / Gate 1 candidate

This crate is an unshipped migration candidate for [Spec #914](https://github.com/lirtual/mcp-workers/issues/914). Gate 0 passed and merged in PR #915; Gate 1 signed WSS transport was merged in [PR #916](https://github.com/lirtual/mcp-workers/pull/916). The native read_file plus file-browsing executors are Gate 1 candidate slices, not overall Gate 1 completion. The TypeScript/Node Agent remains authoritative for Stable releases and all supported platforms. No Stable Release, Worker or GitHub-hosted Session workflow executes Rust.

The existing Linux archive and installer now recognize an explicit Rust candidate profile. The builder requires --rust-agent-bin and --rust-agent-sha256, a Linux glibc target, and a -rust-candidate version; it rejects a Rust ELF whose glibc requirement exceeds the existing Node/Supervisor release limit. The public release verifier additionally requires GitHub to mark that exact tag as a prerelease. The archive layout remains the existing one, with agent_runtime=rust-standard-linux-v1 and the binary beside the existing Supervisor. The installer switches only systemd's Agent executable after the existing Node freeze/receipt checks; the Node bootstrap and manager remain in the candidate package for this migration step. Stable /releases/latest continues to select only the five existing Stable assets. No candidate Release has been created, and package-level systemd activation/recovery with a compatible built Rust binary is still pending; these code checks do not pass Gate 1 by themselves.

### Linux managed-session Supervisor control (nonproduction only)

The Linux-only `linux_supervisor` Rust module reuses the **existing** `agent/scripts/session-supervisor.c` binary and its native fd 3/4 single-byte protocol; it does not create another supervisor, service, dependency or release asset. Rust creates a private process group, passes private control pipes, accepts the ready handshake, and can request TERM, escalate to KILL and close the owning channel. The C helper retains the `pidfd_send_signal(..., PIDFD_SIGNAL_PROCESS_GROUP)` preflight, subreaper and fail-closed process-group cleanup. Rust reports `CleanupState::Confirmed` only when the C subreaper returned normally (excluding ambiguous exit 125); any signal-killed supervisor, including KILL escalation and channel loss, is `Unknown`, even when a particular child is observed dead. No caller-supplied PID is signalled.

Three opt-in Linux tests with the existing C helper passed: owned shell/group TERM, control-pipe EOF, and a TERM-ignoring command requiring KILL. They independently check whether the started child is still executing (a reparented zombie is not a live process). The separate unshipped `linux_output` module now continuously drains both stdout/stderr pipes with a shared **256 KiB** capture cap (it keeps discarding further bytes to avoid child backpressure), paginates by byte offset with Node-compatible UTF-8 boundaries (up to 64 KiB requested), and stops its readers within bounded poll intervals even when a pipe remains open. Four opt-in real Linux tests cover large dual-stream output, early reader stop, multi-byte pagination and the incomplete UTF-8 cap boundary. The output-only `eof` means both pipes closed; any future WSS session response must additionally check process state before promising process completion.

The unshipped `linux_command` module now composes the C Supervisor and bounded output into a **single blocking Linux command** for disposable hosts. It preserves Node's 8192-UTF-16-unit/NUL input check and 60-minute maximum, polls a shared cancellation flag, stops owned descendants on expiry/cancellation, returns the independently observed exit and cleanup status, and waits a bounded time for pipe closure. Output EOF alone never establishes process completion; SIGKILL or uncertain cleanup is explicitly Unknown, even if a particular child appears dead. Seven opt-in real-process checks exercise success, nonzero exit after early pipe EOF, deadline and cancellation with descendant verification, KILL uncertainty, pre-cancel and invalid input.

The blocking proof is deliberately not routed through the Worker (whose response budget is much shorter). The separate, Linux-only **`linux_managed`** candidate adds a background session registry over that same C helper and bounded output capture: startup returns after the native ready handshake, output remains page-readable while the process runs, 10 active/uncertain sessions are admitted, completed history is bounded to 10 and 30 minutes, and a spawn-relative absolute lifetime is capped at 60 minutes. Owner-style bulk stop closes new admissions first and only reports confirmed cleanup after each owned C supervisor was reaped; KILL escalation and any unconfirmed cleanup remain Unknown and conservatively consume capacity. Twelve opt-in physical-process tests now additionally cover UTF-8 stdin roundtrip, invalid input and revoked-session rejection, plus unread-pipe backpressure returning Unknown within a one-second write budget. Stdin writes are nonblocking and bounded to 8192 UTF-8 bytes (Node-compatible); a failed/partial write must never be blindly replayed. A pending owned entry is reserved before native startup, so concurrent revocation never waits on the handshake lock; unproven startup/cleanup retains Unknown rather than being omitted from the registry.\n\nThe additional Linux-only **`native_process`** adapter now connects those owned sessions through the existing signed rc-v2 WSS transport and **the same exclusive SQLite v1 receipt owner** used for file mutations. Node's process operation arguments are normalized before SHA-256 (including `start_process.timeoutMs`); receipt admission and active-lease checks precede effects, while duplicate IDs, conflicts, uncertain restarts, process exit, input and confirmed-stop status are reconciled without blind replay. The existing file-only runner still rejects Shell with policy 1008. The separate `run_native_managed_session` proof explicitly opts into process frames; invalid frames also close 1008, and Owner revocation closes admission before stopping only C-supervised owned processes. Cleanup remains `uncertain` unless every relevant process is independently confirmed reaped.

Seven opt-in actual C-process/SQLite cases, three signed WSS loopback cases, and one isolated **real Owner MCP → Wrangler/SQLite DO → Rust WSS → C Supervisor** case cover Node24-independent process digest goldens, command launch, Unicode stdin/output, duplicates/conflicts, restart Unknown, stop/revoke and failed authorization. The Wrangler test passed with a newly paired temporary identity and a private disposable test root; the real Worker rejected a new challenge after Owner revoke.

### Disposable CLI process-boundary tracer (nonproduction only)

`cargo run --locked --bin rca-native-nonprod -- --local DEVICE_UUID DISPOSABLE_ROOT` launches the existing signed native file session as a standalone Linux, macOS or Windows process. It only connects to the **exact** local Wrangler address `http://127.0.0.1:8777/` and requires a separately approved disposable identity at `gate0-test-key.pem` in an `rca-rust-probe-*` private directory. On Unix the root must be a direct canonical child of `/tmp` (0700; identity 0600, single link); SIGINT/SIGTERM stop the bounded reconnect loop. On Windows the root must be a direct child of the current user's temp directory with a protected owner/SYSTEM-only NTFS ACL; the CLI validates the root and single-link identity file through the existing Win32 handle/ACL guard and handles Ctrl+C/Ctrl+Break. A valid `gate0-test-key.pem.owner-stopped` marker blocks connection; invalid markers fail closed. Installed Node Agent state paths and production endpoints are always rejected. Unix root execution remains disabled; Windows root/elevation policy is a separate unverified gate.

An additional explicit **`--local-managed`** mode runs the existing platform-managed WSS executor in that same disposable CLI, without changing the default `--local` file-only policy. Linux requires `RCA_NATIVE_SUPERVISOR_BIN`, macOS requires `RCA_DARWIN_SUPERVISOR_BIN`, and Windows uses the already-validated native Job Object executor without a C helper. On Unix the selected variable must point to an absolute, canonical, owner-owned, executable C helper with no group/world write or setuid/setgid bits; missing or unsafe helpers fail before connecting or opening receipts. Both modes remain limited to the exact loopback Worker and private disposable root. Linux example with a separately built C helper and an approved **disposable** identity:

```sh
RCA_NATIVE_SUPERVISOR_BIN=/ABSOLUTE/DISPOSABLE/agent/.build/session-supervisor \
  cargo run --locked --bin rca-native-nonprod -- \
  --local-managed DEVICE_UUID /tmp/rca-rust-probe-UNIQUE
```

On macOS, pass the canonical temp path (not the `/tmp` symlink):

```sh
RCA_DARWIN_SUPERVISOR_BIN=/ABSOLUTE/DISPOSABLE/rca-darwin-supervisor \
  cargo run --locked --bin rca-native-nonprod -- \
  --local-managed DEVICE_UUID /private/tmp/rca-rust-probe-UNIQUE
```

On Windows, first create an existing disposable root directly inside the current user's temp directory and seal it with the same protected user/SYSTEM NTFS ACL as the test fixture; place only a disposable private PEM in it. A regular inherited temp ACL or junction fails closed. The command has no helper variable:

```powershell
cargo run --locked --bin rca-native-nonprod -- --local-managed DEVICE_UUID "$env:TEMP\rca-rust-probe-UNIQUE"
```

This is **not** an installed CLI, filesystem sandbox, pairing client or released Agent. A disposable local Worker can still authorize file operations with the current OS user's permissions; execute it only in an isolated, throwaway test host with known temporary file targets. The CLI process rejection/Stop tests are in `tests/nonprod_cli.rs`; the real-Owner WSS/file library contract remains in the opt-in `wrangler_native_file.rs`. The opt-in `wrangler_cli_process.rs` now verifies a **real Owner MCP → local Wrangler/SQLite DO → separate CLI subprocess** with a fresh temporary Grant: write/read, durable status, same-ID no-replay, changed-intent conflict and clean SIGTERM (Pass on an isolated Linux runner). The same test now restarts the process against its preserved private SQLite state, proves a new Owner write succeeds, then revokes the temporary Grant while its WSS is active: the process exits within 10 seconds and a subsequent Owner mutation produces no file effect. Its identity and Owner token come only from a separately approved private `/tmp/rca-gate1-file-*` fixture, never from an installed Agent; the fixture Grant and test files are removed after verification. The separate `tests/cli_managed.rs` executes the real CLI subprocess over signed loopback WSS with the actual C Supervisor: **SIGTERM** stops a live owned Shell, **Owner revoke** waits for confirmed cleanup and exits 0 after safe policy close (as in Node), and the original **file-only** CLI still rejects Shell with 1008 and its existing failure exit. Both managed shutdown paths persist the terminal SQLite receipt before process exit; uncertain cleanup still fails. These tests use independent temporary roots/identities and never contact a production Worker. Installed process lifecycle, five-platform deployment and real-device upgrade/rollback remain unverified.

### Published Node to Rust process handoff (local-only)

The opt-in `agent/tests/rust-release-handoff.mjs` test uses an actual published
Linux x64 v0.1.56 archive (the immutable asset's fixed SHA-256 is checked before
extraction), a freshly built Rust Standard candidate and the existing C
Supervisor. Run only on a disposable Linux host, after installing this
workspace's pinned dependencies. Start the isolated local Worker using
`tests/fixtures/wrangler-rust-handoff.json` and a fresh private state
directory; it must listen only on `127.0.0.1:18777`. Confirm that port
is free before starting the local Worker from the Worker directory:

```sh
  --local --ip 127.0.0.1 --port 18777 --persist-to /PRIVATE/TEMP/worker-state \
  --var MCP_ACCESS_TOKEN:disposable-handoff-owner-token-0000000001
```

From the repository root, build the binaries and run the test with a locally
downloaded immutable v0.1.56 Linux x64 asset:

```sh

```

Stop the local Worker and remove its disposable state afterward.

The test creates a temporary paired identity and private home, then exercises a
Node write, owner-local freeze and exit, Rust signed reconnect with the same
SQLite file, duplicate/conflict checks, missing-helper startup failure, and
manual Node restart with Rust's receipt. It also creates a real running command
and kills the test Node Agent, independently confirms the recorded command PID
has stopped executing, then checks the recovered Unknown receipt and no replay
in Rust and after Node restart. Before that crash scenario, two separately
admitted identical commands produce two real file effects to confirm that the
single-effect assertion detects a duplicate. If the crash scenario cannot be
completed safely, its private evidence directory is retained for inspection.
The Worker maps an Unknown mutation reply to `timeout_unknown`; only
`get_operation_status` reports the stored `unknown` state.

No production Worker or installed identity is used. This is a process-level
proof only: it neither invokes the real installer nor demonstrates systemd
activation, automatic rollback, release authenticity beyond the pinned archive
digest, or an upgrade-ready Rust package.

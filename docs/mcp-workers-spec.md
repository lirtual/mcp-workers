日期：2026-09-15（实施状态更新：2026-09-16）

## 1. 目标与规格边界

将六个独立 MCP 项目的源码维护集中到一个仓库，保留各自 Worker、凭证、资源和部署。降低跨项目修复、检查和新增应用的成本，不建立通用 MCP 平台。

本文是从共识与最终建议收敛的实施规格。显式确认的决定保持不变；公共入口包、CI 和冒烟采用最终推荐的最小实现，不声称用户曾逐条批准所有审查建议。本文不授权自动创建远程仓库、生产变更或归档操作；后续实施按届时任务授权执行。

完整历史审查仅用于查证，不作为额外工作清单。未复现的静态风险不能当成已发生事故，也不能借机扩大重构范围。

## 2. 用户故事

1. 作为维护者，我希望在一个工作区查看和修改六个项目，以便减少切换与遗漏。
2. 作为维护者，我希望修改一个工具只涉及所属应用，以便独立理解、验证和发布。
3. 作为维护者，我希望通过一致的检查入口验证应用，以便不必记忆各项目不同操作。
4. 作为维护者，我希望公共入口问题只需修复一个明确模块，以便避免多个实现逐渐分叉。
5. 作为维护者，我希望新增 MCP 能参考一个已验证应用，以便主要投入业务接口与工具实现。
6. 作为使用者，我希望继续通过 Portal 使用已有工具，以便源码迁移不破坏调用方式和结果。
7. 作为使用者，我希望错误凭证无法访问我的数据，以便保护账户和业务资源。
8. 作为维护者，我希望只维护一种入口凭证方式，并接受短暂维护中断，以便减少兼容和轮换成本。
9. 作为使用者，我希望导出文件通过有期限的链接下载，以便使用方便且不默认永久公开。
10. 作为使用者，我希望超时、过大结果和结果不确定的写入得到明确反馈，以便知道如何继续而不重复操作。
11. 作为维护者，我希望部署失败可以恢复到已知可用状态，以便控制迁移和发布风险。
12. 作为维护者，我希望高风险验证使用临时资源，以便验证真实行为且不长期维护测试集群。
13. 作为维护者，我希望依赖变更的影响被覆盖，并接受偶发扩大检查，以便不维护复杂构建分析系统。
14. 作为维护者，我希望保留来源和许可证记录，以便将来定位历史变更与选择性移植上游修复。

## 3. 架构与依赖关系

### 3.1 仓库职责

- 根目录：pnpm workspace、单锁文件、公共检查工具、简短说明。
- `apps/<worker>`：业务实现、应用依赖、Wrangler 配置、Env 类型、测试、应用 README。
- `packages/portal-auth`：迁移完成后提取的唯一首批运行时公共包。
- `scripts/`：最小 MCP 只读冒烟等仓库工具；不发布 npm 工具链。
- 文档：当前架构、必要 ADR、临时迁移清单。公共规则只维护一份。

不强制应用内部拥有相同分层。使用已有入口、客户端、工具等自然职责；无实际职责的 service/factory/adapter 不新增。

应用不得导入其他应用代码；共享机制通过显式 workspace 依赖引用。公共包不得反向依赖应用。公共包打入每个消费者自己的 Worker 产物，不形成运行时中央服务。

### 3.2 依赖与构建

- 使用 pnpm workspace 和单 `pnpm-lock.yaml`，根 `packageManager` 固定选定的 pnpm 10 版本，Node 基线为 24。
- 源码搬迁与包管理器迁移分离，不同时升级 SDK、TypeScript、测试框架、Wrangler 或兼容日期。
- 从现有锁文件迁移解析结果，核对直接及重要传递依赖变化；不能以删除锁文件并重新解析最新版代替迁移。
- 每应用声明其运行、构建和检查依赖，不能隐式借用根依赖。根目录工具可以声明其自身所需依赖。
- 应用保留兼容日期、TS/ESLint/测试配置及 Env 类型；不同版本允许并存。
- 先验证 Cloudflare 原生安装能发现 workspace 和根锁文件，能冻结解析且不隐式改锁；不满足时使用受支持的显式安装命令，不形成自研安装器。
- pnpm 安装生命周期脚本若被阻止，核实实际依赖所需行为并最小化允许范围，不一律开启全部脚本。
- `portal-auth` 初期直接使用可被 Wrangler 打包的源码；需实测包 exports、类型检查与干净构建，不预设 npm 发布或独立 dist 产物流水线。

### 3.3 隔离范围

Worker、凭证和资源应用级独立；Portal、账户额度、锁文件与部分构建触发共享。不承诺完全故障隔离、原子跨应用发布或独立账户配额。

不新增跨应用共享数据库、服务绑定、中央配置、全局缓存或鉴权服务。

## 4. 应用接口合约

### 4.1 开发命令

每应用提供 `dev`、`deploy`、`typecheck`、`test`、`check`，package 名与应用目录末级一致。实现保持应用本地。

- `check`：不需要生产凭证；包含类型检查、必要本地测试、Wrangler dry-run/build 校验；已有有效 lint 保留。
- 环境依赖的测试使用独立集成命令。缺环境跳过必须报告，不能计为验收通过。
- `check` 已执行 dry-run 时，不重复运行同一项。
- 生产单应用构建不运行整个仓库的递归检查。

### 4.2 HTTP 与 MCP

- `GET /health` 返回 200 和最少 `status`、`service` 信息，不读取上游或存储，不暴露配置和凭证。现有其他健康信息只在无敏感且有用途时保留。
- `/mcp` 使用适配当前应用 SDK 的无状态 Streamable HTTP handler。保持当前工具名、输入输出 schema、资源和提示的既有可用契约。
- 不通过一次性合仓升级协议；取消旧鉴权兼容不自动意味着删除现有协议适配或用户正在使用的功能。
- 错误凭证拒绝；缺必要配置拒绝服务。入口约定使用 401 表示无效/缺失凭证、503 表示入口配置缺失、403 表示无效 Origin。普通未知路由保留 404。
- Origin 缺失允许服务器到服务器访问；存在时按明确允许来源校验，无业务需求时不返回通用浏览器 CORS。不以回显任意 Origin 代替验证。
- 协议方法、状态码和头由应用所用公开 SDK 接口处理，不自研传输解析器。

## 5. Portal 单 Token 与配置

### 5.1 已确认策略

每 Worker 单独配置 `MCP_ACCESS_TOKEN`，值互不复用。取消 `MCP_ACCESS_TOKEN_PREVIOUS`、双 Token 轮换、旧客户端 OAuth 与 Access 回退。

删除旧兼容需同步清理失效的配置校验、环境变量样例、文档、测试和无使用者依赖；不删除 Portal 自身 OAuth、Instapaper 上游 OAuth、数据库只读权限或其他业务授权约束。

入口 Token 仅鉴权使用，通过后移除真实 Authorization，再交给 handler/业务代码。上游凭证由各应用客户端自行构造，不能复用入口凭证。

### 5.2 portal-auth 公共接口职责

输入：Request、预期单 Token、允许 Origin 的应用配置。输出：清理后的 Request，或结构化失败原因。不得读取全局环境，不依赖 MCP SDK/Agents，不创建 Server，不负责资源、权限、日志平台或 HTTP 路由。

保留原请求体及必需协议头。只提取一致的机制；应用将失败原因转换为约定响应，Database 自行构造必要业务上下文。

常量时间比较能力按实际运行时核实，不因函数叫 constantTimeEqual 就认为性质已证明。

### 5.3 配置来源

非秘密绑定/兼容配置在各应用 Wrangler 文件；秘密在应用自己的 Cloudflare Secrets 与本地 `.dev.vars`，本地秘密不提交。

入口读取并校验，再显式传入必要字段。避免服务内部重新读取 process.env；Node 设置脚本可以在其入口读取环境。不引入 DI 容器和公共 Env。

README 只记录配置入口和 Dashboard 独有设置的操作说明，不抄写第二套完整配置。

### 5.4 单 Token 维护

允许短暂中断。切换前记录不含秘密值的目标版本和配置步骤；先准备可恢复的匹配状态，再更新 Worker/Portal 并验证。

回退必须恢复一致的代码、配置及凭证状态，不能只回滚代码。若 Token 因泄漏撤销，不通过恢复旧 Token 回退，使用新的有效凭证。退回旧鉴权代码需识别其安全语义，不能静默恢复已淘汰访问路径。

## 6. IMA 临时下载

这是 IMA 独立功能修正，不建立共享下载平台；不改变其他应用存储结构。

- 持有链接即可下载，无需登录；链接限制到具体对象和到期时间，篡改或过期拒绝。
- 使用成熟密码原语进行签名校验，不将 MCP_ACCESS_TOKEN 放进 URL。签名密钥为 IMA 独立用途秘密，不属于双入口 Token。
- 所有受保护导出的实际读取路径必须校验；旧 /download 与公开 R2 域名不能继续绕过。发现公开直链时纳入切换步骤。
- 缓存策略不能使过期链接继续从未校验路径读取受保护对象。
- 对象键使用服务端生成的唯一导出标识，避免重复导出覆盖后旧链接意外指向新内容。
- 链接期限与对象保留期限分离；对象过早缺失返回明确不可用，不返回虚假成功。
- 实现默认值：链接有效 1 小时、临时导出对象保留 7 天。这是未被用户指定的可调整工程默认值，不是历史共识。应用配置可调整，保留周期至少覆盖链接期限；采用可用原生生命周期配置，暂无原生清理条件则明确实现缺口，不额外建设调度平台。
- 生成新链接需要正常授权流程；不保存下载会话表，不要求逐链接撤销、访问统计或永久分享。

## 7. 检查、发布与观测

### 7.1 CI 与触发

一个普通检查工作流复用环境准备和各应用 check，Database 保留独立数据库集成 job。各应用现有测试框架保留；不做跨框架公共测试库。

| 修改 | 检查范围 | 生产触发 |
| --- | --- | --- |
| 单应用业务代码/配置 | 本应用及相关本地/集成测试 | 该 Worker 原生 Builds |
| 根锁文件/workspace 安装配置 | 六应用 | 接受六 Worker 被触发 |
| 公共入口包 | 所有消费者；初期全检查可接受 | 监视该包的消费者 |
| 纯文档 | 必要格式/链接检查或无执行检查 | 正常情况下不发布 |

用简单路径规则，不建设依赖闭包分析器。必需检查给出明确结果，避免未触发任务导致无限等待。分支保护按实际 GitHub 套餐可用能力配置；没有服务端保护时不能冒称强制门禁已生效。

生产只由 Cloudflare Builds 发布。GitHub Actions 不配置第二套生产发布链。已存在部署 gate 保留；检查所需环境不具备时不得将失败忽略后发布。

### 7.2 MCP 冒烟

使用已有公开 SDK 客户端，输入实际 MCP 地址、通过安全环境注入的凭证和应用明确指定的只读用例。连接、工具发现与用例调用在一次流程中验证。工具注解只作参考，不据此自动调用所有工具。

本地公共包测试和 Worker 入口测试不需要生产秘密。Portal 真实调用是上线验收的一部分，不能由只测 Worker 直连接口代替。Portal 自动化访问条件不足时记录真实人工验证结果，不造 Portal 配置同步层。

### 7.3 日志

使用 Cloudflare 原生日志，字段最少包含定位应用/操作/结果所需信息。秘密、正文、数据库结果不默认记录；未知异常对用户使用安全消息。

利用已有构建记录关联源码提交与 Worker 版本。package 版本不当作生产部署身份。不建追踪平台、发布数据库或指标系统。

## 8. 实施阶段

### 阶段 A：固定事实和建立基线

1. 读取各仓库实际 HEAD、适用 AGENTS/CONTEXT/ADR、配置、检查命令、GitHub/Cloudflare 部署连接。
2. 保存源 commit SHA（不要用历史 Git tree SHA 冒充）、工具契约、实际入口和资源标识；不收集真实秘密值。
3. 先选已验证、状态依赖最少的应用试点，默认优先考察 weread；如果实际入口或基线不通过，先解决具体阻塞或改选已可用应用。
4. 只阻止相关应用不安全/不可验证的迁移，不要求六应用历史缺陷全部清零。

交付：基线及试点检查清单。没有运行证据的项目标记未验证。

### 阶段 B：逐应用搬迁源码

1. 以稳定快照迁入 apps，不合并全历史；记录源仓库、commit、许可证。
2. 保持原应用行为、依赖解析、Worker 名称、资源标识和运行地址；不同时修改工具名称、鉴权或格式化。
3. 各应用本地验证，再切换其 Builds 源码目录并验证 Portal。
4. 每个 Worker 任一时刻只保留一个有效自动发布源，先停用旧触发再启用新触发；允许短暂维护中断。
5. 当前应用通过验收再移动下一应用。旧仓库先保留，最终验收后才归档。

交付：六应用源码集中且既有行为可用。此阶段允许暂保原包管理文件，避免混合变更。

### 阶段 C：工作区和检查流程

在独立变更采用单 pnpm workspace/锁文件，核对实际依赖变化。统一 app scripts、普通 CI 和 Watch Paths；验证云端干净安装、构建与冻结锁文件。移除已被替代的旧锁文件，不升级业务依赖。

交付：根工具链可用、单应用发布可用、共享变化影响被覆盖。

### 阶段 D：收敛 Portal 入口

在独立行为变更中完成单 Token 命名、移除旧鉴权兼容、配置要求清理、Origin 和浅 health。提取窄 portal-auth 后验证所有消费者。源码搬迁时保留旧行为不等于目标方案长期兼容；本阶段结束必须达到 Portal-only 目标。

交付：六应用入口一致，业务授权不退化，单 Token 切换和回退步骤明确。

### 阶段 E：相关修正与收尾

IMA 完成临时下载保护。相关应用处理下表中的实际验收阻塞项，其他问题记录为独立后续工作。完成 Portal 真实调用、日志与回退核对，停止旧发布源并归档已验收旧仓库。整理简短当前设计与应用说明，不复制整份历史审查进各 README。

## 9. 已发现缺陷的处理边界

| 项目/事项 | 实施要求 | 不扩大到 |
| --- | --- | --- |
| Raindrop 写操作通用重试 | 对实际写工具验证一次提交，去除不安全自动重试 | 全局幂等平台 |
| Raindrop 请求内缓存/限流/订阅 | 确认用途和生命周期；仅删除无效或未使用机制；正在使用的协议能力单独处理 | 分布式缓存/订阅系统 |
| Raindrop 私有 SDK 字段 | 查真实调用方；可移除则移除，否则使用公开接口或现有定义 | 第二套注册框架 |
| Raindrop 隐式 process.env | 收敛为入口显式配置；不宣称现状必然不能运行 | DI 容器 |
| Database 迟到连接 | 可控延迟验证竞态，若成立补清理；现有连接/只读集成测试保留 | 驱动通用生命周期框架 |
| IMA URL 前缀误拒绝 | 区分域名/IPv4/IPv6，验证误拒绝与重定向处理 | 未验证的通用 safeFetch |

这些修复与迁移提交分离。明确访问风险不得因“减少范围”而绕过验收；非阻塞疑似风险不强制变成合仓前置工程。

## 10. 验收矩阵

| 编号 | 场景与期望 | 验证边界 |
| --- | --- | --- |
| AC01 | 干净检出可按约定安装并完成各 app check；锁文件无意外改动 | 真实本地/CI/Cloudflare 构建 |

| AC07 | 工具名称和 schema 与基线一致，已计划鉴权变化单列 | MCP tools/list/代表性调用 |
| AC08 | 真实 Portal 能发现并调用各应用指定安全工具 | Portal 到上游完整链路 |
| AC09 | 六应用仅保留目标入口鉴权，无旧配置要求；Database 只读约束有效 | 入口负例、真实数据库集成 |
| AC10 | IMA 链接有效时下载，过期/篡改拒绝，旧路径不可绕过；对象清理已配置 | IMA 入口及实际绑定环境 |
| AC11 | 非幂等写遇不确定失败不自动重复提交；超时有明确结果 | 应用公开操作＋可控上游替身 |
| AC12 | 相关连接在失败/超时后释放，已确认竞态有回归验证 | Database 适用集成边界 |
| AC13 | 新旧仓库不会同时发布同一 Worker；回退记录与目标版本匹配 | 部署配置与验收记录 |
| AC14 | 高风险测试使用临时资源/可清理数据，无生产写入冒烟 | 测试配置与执行记录 |
| AC15 | 新工具不修改中央注册器/共享 Env；无需创建新公共包 | 变更审查 |

保留各应用既有有效测试。无需新增测试框架；纯文档改动不执行生产冒烟。实际未执行项标记 Not run/Blocked 并说明原因，不伪记 Pass。

## 11. 不在范围内

- Quark MCP、多租户、用户管理、RBAC 平台。
- 合并为一个 Worker，或构建 worker-core/中央工具注册/统一客户端基类。
- Turbo、Nx、Lerna、Changesets、统一版本列车。
- 强制 SDK/测试框架/TS 配置全部统一，迁移夹带依赖升级与全量格式化。
- 旧入口鉴权兼容、双 Token、零停机承诺。
- 常驻 staging、全局幂等账本、共享存储、Portal IaC/配置同步、额外生产发布链。
- 自动生成器、跨框架测试库、通用 I/O/日志/配置包和精确依赖分析。
- 未经独立确认删除用户正在使用的工具/协议能力。
- 全部历史缺陷清零、全仓安全审计或对维护收益的固定百分比承诺。

## 12. 完成与交接

完成意味着六应用逐个通过迁移验收，Portal 单 Token 目标落实，新增工具仍局限于应用，公共入口修复有单一复用点，日常检查与发布成本可接受。达到后停止主动扩大架构。

证据记录只需源 commit、目标 commit、Worker 版本、关键检查结果与回退路径，复用现有 CI/Builds 日志，不建新系统。

本文最初以 `ready-for-agent` 状态交付；当前文首 `source-ci-accepted` 表示源码实现、统一 CI 和最终 pruning 已验收，不代表生产部署、Portal live 调用、publisher 切换或旧仓库归档已经完成。需要接入任务跟踪时运行 `/setup-engineering-workflows` 指定目标，再发布规格/拆票；这不是阅读或使用本文的前置条件。

实现前的必查项为实际 HEAD、入口/绑定、Cloudflare 安装行为与 GitHub gate 可用性。已完成的历史静态审查无需重做，除非代码或外部约束发生变化。

## Repo findings requiring design follow-through

- `src/registry.ts` and `src/scheduler.ts` consume generated `src/generated/workflow-registry.ts`; `admission.ts` persists pinned versions on admission. Introduce runtime registry reads without creating a second plan interpretation path.
- `src/compiler.ts` is Node/YAML/Zod based. Decide whether publication compiles in CI and runtime verifies compiled data only, or a separate Workers-compatible validator is necessary.
- `src/connections.ts`, `effective-policy.ts`, and `compiler.ts` currently resolve a static Connection/policy. Define source and versioning of approved connection metadata, with no new business credential vault.
- `scheduler_state` is keyed by workflow/trigger; design cursor handoff when a changed cron/timezone shares this key, and bound work per tick.
- `workflow_definition_versions` already stores immutable plans by digest. Define the active-registry pointer and an atomic activation protocol, including existing bundled definitions on migration.
- The shared `MCP_ACCESS_TOKEN` is entry authorization only (ADR 0028); v0.2 publication/admin authority must be separate.

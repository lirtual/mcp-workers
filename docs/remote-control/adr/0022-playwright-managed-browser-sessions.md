# ADR-0022 — Playwright-backed, cross-platform browser sessions

> **Superseded for phase-one runtime selection (2026-10-20):** The direct Playwright-library runtime choice below is part of the earlier Q5 design history, **not** the present phase-one decision. Real Windows [CLI head-to-head PoC](../BROWSER-BACKEND-POC-20261020.md) passed with **agent-browser** and Microsoft Playwright CLI on separate Profiles. Select **agent-browser as the single first integration candidate**, with Playwright CLI only a fallback if integration evidence reveals a blocker. Reuse its mature Snapshot Ref/session semantics instead of building a custom registry. Keep all previous identity, isolation, authorization and non-replay boundaries; no CLI/Shell pass-through or production runtime is approved by this docs edit.


Status: **accepted design choices (Grill With Docs round 2, 2026-10-20); documentation only; implementation and release not authorized**.

Browser control will be implemented **inside the existing Remote Control Agent using the Playwright library**, wrapped by the Remote Control MCP's **curated, explicitly reviewed browser tool surface** (Q5=A). Chromium DevTools Protocol (CDP) may be used behind this adapter when appropriate; direct hand-written CDP as the primary product interface, nested Playwright MCP servers, publicly reachable debugging ports, and an arbitrary tool pass-through are not selected. The intent is to reuse mature page automation while retaining one MCP authorization and device-routing boundary.

The initial product target is **Linux and native Windows**, with WSL2 supported as a Linux runtime; **macOS follows later** (Q6=A). Each target requires its own real Agent/browser compatibility and acceptance evidence before release. A platform target is not evidence that native Windows browser automation is already shipped or that WSL2 can control the Windows host's desktop browser. [ADR-0023](./0023-browser-runtime-profile-interruption.md) subsequently selects on-demand provisioning of Playwright-compatible Chromium without implicit OS privilege escalation. Exact trusted download mechanics, installer integration, packaging and platform-specific rollback remain open. [ADR-0024](./0024-browser-observation-and-confirmation.md) subsequently selects headless by default and headed only when a usable local GUI exists.

An **Automation Browser Profile** is a **dedicated, locally retained browser-data profile separate from the owner's regular browser profile** (Q7=A). It can retain sign-in state between automation sessions and supports owner-initiated clearing. No implicit use of the owner's existing Chrome/Edge profile and no upload, central copy or synchronization of cookies/secrets to Cloudflare is approved. [ADR-0023](./0023-browser-runtime-profile-interruption.md) subsequently limits the initial design to one automation profile per device and one active session per profile. Storage location, conflict handling and safe deletion mechanics remain open.

An **Automation Browser Session** has an explicit identity, is reusable across multiple MCP tool calls, can be closed deliberately, and is **eligible for local idle-timeout cleanup** (Q8=A). An interruption or disconnect must never automatically replay a browser action. [ADR-0023](./0023-browser-runtime-profile-interruption.md) subsequently chooses local session retention during caller disconnection, Agent-side idle cleanup, no automatic replay, and best-effort session stop on authorization revocation. [ADR-0024](./0024-browser-observation-and-confirmation.md) subsequently fixes the initial idle threshold at 30 minutes; precise activity accounting, behavior across Agent restart, browser-process ownership, admission limits and action receipt/reconciliation rules remain open. A Browser Session is not automatically the Agent's existing Shell **Managed Session**.

**Trade-offs:** Playwright is a maintained dependency rather than a thin CDP protocol layer, but avoids maintaining a browser-specific automation engine; a separate persistent profile requires local data care but avoids accessing the user's everyday session by default; explicit, idle-bounded sessions permit multi-call workflows without permanently owning a browser process.

Related: [ADR-0021](./0021-browser-automation-extension.md), [browser design tree](../BROWSER-AUTOMATION-DESIGN.md), [domain terms](../CONTEXT.md). This decision does not modify the v1 scope or authorize coding, additional Tickets, deployment or production changes.

# ADR-0022 — Native macOS Agent without weakening owned-process safety

**Status:** Accepted design direction (2026-11-01); **not implemented or released**. Source: [macOS Agent Grill With Docs, Q1–Q15](../MACOS-AGENT-DESIGN.md), especially Q2/Q5/Q6/Q14. This extends the original Linux-first [ADR-0001](./0001-linux-first.md) platform scope; it does not discard existing Linux or Windows safety mechanisms.

RCA will support personal **macOS 15+ ARM64 and Intel x64** through its existing bundled **Node.js 24 Agent**, pairing, signed WSS, file/search/Shell, SQLite operation receipts and one reviewed release channel. **Owned Managed Sessions on macOS will use a small native Darwin process Supervisor**, kept within the existing Agent execution/receipt boundary, rather than sharing Linux-only pidfd/subreaper code or relying on unchecked Node.js/POSIX numeric-PID killing. Permanent operation is a **non-root, login-scoped user LaunchAgent**; temporary operation is foreground with the original fixed 24-hour grant. No privileged LaunchDaemon or parallel process manager is allowed.

**Trade-off:** A platform-specific Mach-O helper and native tests are necessary to respect the established **owned-process-only** stop/timeout/revocation invariant. Darwin cannot provide the identical Linux pidfd guarantee; if an owned process/group cannot still be proven safe to signal, the Agent **fails closed**, preserves **Unknown** outcomes and does not target arbitrary PIDs or claim universal descendant cleanup. If native host acceptance cannot demonstrate a safe bounded lifecycle, macOS support is **blocked** rather than relaxed. Windows Job Object and Linux pidfd paths remain unchanged.

**Separate reversible distribution decision:** The initial macOS Release is **not required to be Developer ID signed/notarized** (Q7=B); this must be disclosed, requires individually reviewed immutable assets and real Gatekeeper tests, allows only supported **manual owner** OS approval, and can block launch. It never authorizes automated Gatekeeper bypass. It is not a reason to redesign the Agent, introduce a new Worker or require separate credentials. Do not infer implementation, PR merge, publication, host installation, or production authorization from this ADR.

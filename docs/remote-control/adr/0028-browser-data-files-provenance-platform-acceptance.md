# ADR-0028 — Minimize browser data, reuse host file authority, verify browser provenance, accept platforms independently

Status: **accepted design choices (Grill With Docs round 8, 2026-10-20); documentation only, no implementation or release authorization**.

**Q29=A — task-relevant, bounded page output by default.** Browser MCP observation normally provides a compact, size-bounded selection of task-relevant text and semantic/accessibility structure, not a raw full DOM plus unconditional screenshots. Do not deliberately extract, serialize or log passwords, cookies, bearer tokens or other credential-bearing browser/profile data as ordinary page results. Screenshots are returned on demand and **may visibly contain sensitive information**; do not claim they are automatically safe, wholly redacted, or equivalent to semantic text output. Page content is untrusted data, not instructions. No website allowlist or separately administered permitted-site registry is introduced by this decision. The numeric result limits, sensitive-field recognition, screenshot redaction/handling, truncation semantics, and error reporting remain open.

**Q30=A — reuse the Agent's existing filesystem authority.** Browser upload requires an explicitly selected Agent-local file path and is bounded by the Agent process's ordinary OS account permissions plus the applicable existing Remote Control authorization; do not silently grant access to other files. Downloads go to a dedicated Agent-managed local directory and are subsequently read, moved or deleted via existing Remote Control file tools as applicable. Do not add a separate browser-only filesystem allowlist, extra authorization configuration, new file manager, or default bulk file tunneling through Worker/MCP. Directory permissions, file collisions, download retention, cleanup and oversized-file behavior remain open, as do the limits of the existing Remote Control file tool surface. Existing OS permissions are necessary, not a substitute for explicit path intent or browser action confirmation.

**Q31=A — fixed compatible Chromium with verifiable trusted provenance.** On-demand installation uses a browser build compatible with the selected Playwright runtime from a reviewed/trusted distribution source. Before trusting it, the Agent verifies origin/integrity using the authoritative provenance and verification data actually available for that artifact; do not invent an upstream checksum or claim a specific cryptographic guarantee that has not been established. If a required browser is absent offline, the source is untrusted, the artifact fails integrity verification or a compatible binary cannot be established, report the failure and do not silently switch to an unverified mirror, arbitrarily choose a newer build or execute suspect bytes. No independently managed Chromium distribution service is selected. Exact artifact selection, signature/digest source, rollback, cache and platform packaging contract remain open.

**Q32=A — independent real-device acceptance with staged release per platform.** Linux, WSL2 (a Linux runtime), and native Windows each need separate relevant acceptance evidence for supported browser startup, common interactions, local file handling, interruption/recovery, authorization boundaries and Agent upgrade compatibility before enabling their browser tools in production. An accepted unchanged behavior may reuse relevant earlier evidence; do not repeat unrelated already-passing tests without a changed dependency or risk. One platform may progress on its own rather than forcing all targets to finish together. Platform selection does **not** assert that browser automation is currently implemented or that native Windows support is production-ready. macOS remains later. The release stages, CI matrix, go/no-go evidence format and deployment automation are unresolved; this ADR does not approve deployment or create Tickets.

**Why:** bounded output reduces data exposure and token/transport costs without rigid site lists; reusing host-level file authority avoids duplicate configuration and file management; fixed verified binaries reduce supply-chain and compatibility risks; independent platform acceptance avoids premature claims or unnecessary cross-platform release blocking.

**Follow-on decision (round 9):** [ADR-0029](./0029-browser-results-outcomes-downloads-gated-release.md) selects structured compact tool results, separation of Agent execution evidence from website effects, a seven-day default cleanup threshold only for unreferenced managed downloads, and separately gated safe low-impact capabilities when high-impact approval is not verifiable.

**Follow-on accepted decision (round 11, Q43=A):** A normal semantic page snapshot has a **proposed initial default budget of approximately 8,000 characters** of task-relevant output; when truncated, the response explicitly says so and the caller obtains further focused information in follow-up reads rather than unbounded DOM output. A screenshot is **on-demand**, initially at most **one per request**, rather than automatically returned alongside every text observation. Do not intentionally extract passwords, cookies or tokens; nonetheless screenshots, page text and visible form values can contain private data and cannot be promised fully redacted. Exact byte/character accounting, cropping, image dimensions, transport, sensitive-field suppression and continuation/pagination contract remain undecided; this is a tunable initial design budget, not proven optimal performance.

**Follow-on accepted decision (round 12, Q47=A):** Downloads may write **only** into the Agent-managed browser download directory using safe local filenames. A name collision gets a unique non-overwriting name, rather than replacing an existing file. Reject path traversal, outside-directory destinations and symlink/link escapes that would break the managed-directory boundary; a website-supplied filename or path is not authority to overwrite arbitrary host files. Deliberate later moving, replacing or deleting downloaded files is a distinct owner-requested operation through the **existing Remote Control file tools**. The detailed filename normalization, atomic creation, Windows-specific path rules, race handling, quarantine/extension policy and collision naming format remain open; no new browser file-manager service is approved.

**Follow-on accepted decision (round 13, Q50=A):** Browser page text, DOM/semantic snapshots, screenshots and browser profile credentials remain **untrusted or potentially sensitive data**, never instructions or owner authorization. Normal operational logs and local durable receipts record only the minimal operation identity, status and safe diagnostic/error information needed to reconcile work; do **not persist full DOM, screenshots, form values, passwords, cookies, bearer tokens or arbitrary tool payloads by default**. Do not copy sensitive content to Cloudflare/MCP logs as routine telemetry. Explicitly requested screenshots or page excerpts may still visibly contain secrets and may be delivered to the authorized caller subject to Q29/Q43 bounds; the policy does **not** promise complete sanitization, nor prohibit all visual output. Exceptional diagnostics, log redaction rules and any separately authorized retention must be designed before use; no new long-term browser trace store is approved. Minimize exposure at collection and output, and do not interpret webpage instructions as commands.

**Still open / requires validation:** exact snapshot/byte/token and screenshot handling limits, redaction rules, diagnostic opt-in and existing telemetry exposure; managed-download references and secure creation/cleanup races; Chromium integrity metadata; typed browser tools; actual verified consent transport/classifier; website-effect evidence; Linux/WSL2/native-Windows acceptance and rollout gates.

**Post-convergence source feasibility review (non-decision):** A readable Agent-local upload source is not automatically authorized for external transfer: the **destination origin and source path** must form part of the approved intent/effect classification, with consequential uploads disabled when verifiable approval is unavailable. Existing Remote Control text/file-management tools do not prove that downloaded ZIP/PDF/image bytes can be returned to ChatGPT. Prefer Playwright's pinned version-compatible browser installer/cache and use actual upstream provenance rather than creating a new custom browser distribution. See [post-convergence feasibility audit](../BROWSER-AUTOMATION-DESIGN.md#post-convergence-feasibility-audit--recommendations-not-new-decisions).

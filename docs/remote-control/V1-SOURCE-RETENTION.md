# Private Agent source retirement — v1 retention gate (#80)

**Status:** Draft migration boundary only (2026-10-18). No source deletion, v1 cutover, merged PR, device enrollment, release, production deployment or #57 soak is authorized by this document.

## Present boundaries (confirmed from code, not inferred cloud behavior)

| Concern | Current source/owner | What would break if private Agent sources were removed too early |
| --- | --- | --- |
| **v1 production lineage** | `apps/remote-control-agent/src/main.ts` starts `server.ts` (native loopback HTTP Agent); `apps/remote-control-mcp-worker/src/worker.ts` still supports v1 via `REMOTE_CONTROL_DEVICE` VPC binding and `REMOTE_CONTROL_DEVICE_TOKEN` | Existing running host process might keep running, **but future v1 service repair, rebuild, fresh deployment, rollback and incident response could lose their reviewed source path**. Do not infer a live host's installed path or version from this repository. |
| **v2 Preview** | Worker/DO lives in the private repo; Linux/WSL2 Agent is packaged and released independently by public `lirtual/remote-control-agent`; the reviewed Preview installer is currently pinned to immutable public v0.1.8 | An inadvertent v1 deletion or private test import rewrite can silently affect recovery and source compatibility, even when the current v2 Preview continues to operate. |
| **Worker CI** | Existing `.github/workflows/ci.yml` swaps a pinned public Agent checkout into the historical private workspace Agent path for the existing typechecks/protocol suite and restores the private directory after checks | This proves public v0.1.8 *test* compatibility but **does not** prove production v1 has a safe independent rebuild/recovery origin. No extra CI workflow is needed. |
| **Local identities/receipts** | Device private key/ID and SQLite receipt paths belong to the host user, not a Git repository | Never delete, migrate or publish them as a source-tree cleanup. Preserve unknown/guarded outcomes; no blind operation replay. |

## Minimum source-removal prerequisites

1. **Establish v1 rebuild provenance, without displaying secrets.** Owner-approved read-only inventory of the actual existing v1 host/service: exact source commit/archive, binary/service command, target user, and dependency on its current checkout or working directory. Record only nonsensitive paths/identifiers and file metadata, **not** device tokens, PEM contents, SSH/Tunnel credentials or receipt rows. If the live host is unavailable, this remains **unverified** and blocks deletion.
2. **Retain a recoverable v1 source route.** Preserve the precise reviewed v1 code and build/installation entrypoints in the original private repository's retained immutable Git history or a separately reviewed private recovery ref/artifact. Prove that an operator can reconstruct the same v1 Agent **without** accidentally installing v2, changing Worker secrets or touching the existing local SQLite. Do not publish v1 credentials or private history to the public Agent repository.
3. **Isolate Worker test dependencies in a distinct Draft change.** Rewrite only the private Worker's direct relative test imports/build assumptions to use a fixed **reviewed public commit** (current v0.1.8 `4d58ffe33e560d6f5f1c375aacf02a774b51a6c0`) in the existing test-only staging path. Keep v1 source available until this change is reviewed and passes existing CI; do not use a mutable branch and do not add a new workflow.
4. **Source-only cutover review.** After (1)–(3), propose a separate explicitly reviewed Draft that removes the duplicate private source/workspace binding, updates `pnpm-workspace.yaml`, lockfile, TypeScript test paths, parent Spec/ADR references and any affected install/recovery documentation. Require existing Application checks, Database integration and pinned-public compatibility to pass on the **new** source layout. CI passing on the **old** source layout is not enough.
5. **Independent production decision.** Verify safe v1 rollback/rebuild instructions and obtain explicit approval before merging or using Cloudflare production/manual release. Preserve the deployed v1 Worker, VPC/Tunnel bindings, Secret values, runtime permissions and existing device/receipt state. Do not claim the #57 genuine 48h gate has passed.

## No-go / stop conditions

Stop source removal if the actual v1 host provenance is unknown, a test still depends on unretained private Agent code, the public pin drifts, any v1 recovery path is unreviewed, or a cleanup would touch a running service/user identity/receipts. No speculative recovery commands, automatic rollback of Cloudflare versions, or hidden emergency credential restoration.

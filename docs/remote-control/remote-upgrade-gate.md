## 2026-11-02 · macOS Remote Control-only upgrade source gate

The original requirement is that already paired, owner-ON permanent macOS devices can be upgraded via Remote Control Shell without any local Terminal keystrokes, while the established interactive one-click installer remains available. The production `v0.1.49` Agent/public Worker installer **does not** implement this; it supports only owner-interactive `--upgrade`. A same-user, one-shot independent launchd dispatcher is a separate candidate in `lirtual/remote-control-agent` PR #111, with existing native macOS ARM64/Intel CI. No new permanent updater, Worker, pairing mechanism, service, database or release flow.

The current Worker release pin deliberately omits `remoteUpgrade: true`; production users do **not** receive or see the new remote action from this source change. The Worker only generates `--remote-upgrade` if and when a separately reviewed, newly published immutable Agent Release is pinned with that explicit capability. The bootstrap then verifies the exact release archive and source SHA-256, and passes the action to the packaged, one-shot launchd launcher. `status=launched` must never be reported as upgrade completion. Real Mac proof requires observing a new signed WSS session, unchanged device ID and durable SQLite receipts.

Agent Release Pin/Tag, Worker protected production publishing and the actual original Mac upgrade remain separate owner-authorized gates. Keep Spec #657/#660 open; the previous four owner-waived real-host scenarios remain Waived; no non-waived TCC/APFS/Gatekeeper negative checks are implicitly accepted.
